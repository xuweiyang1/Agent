Make the local chat assistant remember, and give it a page worth opening

The stage-one deployment was a form in front of the chain, and using it
surfaced three defects that made it a demo rather than a Tuesday tool:

- The transcript lived in a browser variable, so a reload -- let alone a
  restart -- wiped it. Turns are now appended to state_dir/chat.json and the
  page renders that file on load. Plain JSON, so a human can read or repair it.
- W5's long-term memory had no write path, so "it remembers you" was false.
  agentkit/tools/memory.py exposes one memory tool (preference / decision /
  fact, plus list and recall), and each turn injects LongTermMemory.context_for
  into the system prompt. A stored preference is therefore a constraint on the
  next answer, not a diary entry.
- A todo created in chat was never persisted: the chat registry used the
  in-memory services, so /state could never see it. The registry now gets
  Todo/Calendar/Note services rooted in state_dir, shared with the chain.

agentkit/tools/notes.py adds the assistant's own scratch space, kept apart
from the sandboxed user files on purpose. The page is rebuilt: sidebar tool
list generated from the live registry, memory and token readouts, tool-call
chips, replay of stored history, and a clear-conversation button that leaves
long-term memory and todos untouched.

Two tools are opt-in (with_memory / with_notes) so build_registry() stays
constructible with no arguments and no filesystem, which every week's tests
rely on. 10 new tests; full suite 446 offline.
